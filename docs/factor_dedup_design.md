# 因子归纳去重（Factor Consolidation）设计

## 背景

反思归因机制会把每次结算提炼的因子名直接写入 `factor_perf`，未做去重。
现状：梭哈2狗因子库 77 个，其中 480 对名称相似度 ≥ 0.5（如
"离散平局凝聚去下盘 ~ 离散平局凝聚下盘" 0.94、"离散凝聚上盘深盘 ~ 离散凝聚上盘" 0.86）。
重复因子让 prompt 因子段膨胀，也是此前"只注入 main+aux"改动的起因；但那次改动把
上下文护栏一起删了。本方案在**源头**去重，保留全量注入。

## 触发点（关键）

只在**因子记录时**（反思归因把订单写进 `record_factor`）执行去重。
**生产环境不做历史回填重排**——回填属于用今天的信息改写过去，是未来泄漏。

## 1. 相似度判定（LLM 判重，不用硬编码词表）

去重发生在反思归因环节，非实时，因此判重交给 LLM：

- **确定性预筛（唯一保留的规则）**：用通用字符串序列相似度
  （difflib，无中文词表）把候选与现有因子比对，筛出相似度 ≥ 0.45 的 Top-6 短名单；
  无短名单 → 直接新建，不消耗 LLM。
- **LLM 判定**：把候选因子（名称+描述）和短名单（名称+描述+状态+样本+盈亏）交给
  LLM，按规则输出 JSON：
  - 语义重复（同义改写/同模式）→ `merge`，并指出合并目标；
  - **方向相反（上盘 vs 下盘、让球方 vs 受让方、追强 vs 防冷）→ 绝不合并**，`create`；
  - 与 retired 因子重复 → `suppress`（不新建、不复活）；
  - 候选与某现有因子样本都充足且盈亏方向相反 → `create`（经验上不同的模式）；
  - 全新模式 → `create`。
- LLM 输出无法解析 → 保守新建（失败安全）。

## 2. 自适应与防过度合并（内嵌在 LLM 判定里）

- **膨胀自适应**：提示词可附带"因子库当前数量 / 近 7 天新建速率"，让 LLM 在
  膨胀期更倾向 merge；信息只用过去创建时间，不偷看未来。
- **数据逃生**：短名单条目带样本数与累计盈亏，LLM 据此判断"经验上是否已是不同模式"。

## 3. 合并策略

候选因子 C 与库中最相似因子 E：

- `similarity(C,E) ≥ T` 且 `E.status == retired` → **压制（不合并、不新建）**：
  订单归因记录到"已知陷阱日志"，prompt 负例护栏展示它；已退役因子不复活。
- `similarity(C,E) ≥ T` 且 E 非 retired → **合并到 E**：
  - 保留 E 的名称与 id；把 C 的名称加入 `aliases`（后续比对可命中同义改写）；
  - 当前订单的归因写入 E（hit/profit 进 E）；
  - 若 E 当前 dormant 且有新触发 → 状态回 active（近因，无泄漏）。
- 否则 → **新建因子条目**。

## 4. 统计累加（合并后重算）

合并后按 E 的合并历史重算：

- `history`：候选历史 + 原有历史按日期归并排序，按 `(lota_id, date)` 去重；
- `total = len(history)`；`hit/miss/push` 从历史重数；
- `profit = Σ profit`；`total_return` 沿用现有口径（累计回报）重算；
- `first_seen = min(日期)`，`last_seen = max(日期)`；
- `status`：非 retired 保持/恢复 active；retired 不参与合并（见上）。

## 5. 防未来泄漏约束

1. 去重决策在记录时点 T 完成，输入只有：候选定义（T 时刻 LLM 产出）+
   截至 T 已存在的因子（历史条目 date ≤ T）。
2. 生产环境不做历史回填重排；合并一旦做出不再因后续结果撤销。
3. 阈值自适应只用过去的创建速率；不使用未来胜负数据调阈值。
4. 模拟验证（retest）里可以对历史库做"as-if 从头开启"的重放，
   但那只用于评估规则效果，不直接改生产数据。

## 6. 落地位置

- `src/memory.py::record_factor` 前加 `consolidate_factor(candidate, library)`
  返回 `merged(existing_id) | created(new_id) | suppressed(retired_id)`；
- `factor_perf` 条目增加 `aliases: []` 字段；
- 归因统计与现有 `factor_profile` 兼容（去重后因子样本更集中，画像更可信）。
