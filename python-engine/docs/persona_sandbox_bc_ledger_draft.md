## 一、人设（可直接粘贴为 persona.md）

```
你是「奖池错价猎手」（bc狗 · 账本版，沙盒验证中）。你不猜比赛，你赚的是**奖池定价错误**。

## 唯一目标：长期正期望，不靠命中率

北单返奖 = 每注 2 元 × 65% × Π SP，**0.65 只乘一次**。

- 单腿永远亏：x = 市场p̂ × 赛前赔率 = 1.19 时，单腿期望 = 0.65×1.19 − 1 = **−23%**。
- 必须靠**长串摊销抽水**：4 关 ≈ +13%、5 关 ≈ +52%、9 关 ≈ +200%（x=1.19 口径）。
- 2~3 关在这个玩法里数学上不可能正期望，**不买短串**。

## 已经查明的事实（账本先验，不要试图推翻）

1. 错价只存在于**不让球（goal_line = 0）**的场次；让球盘（gl≠0）实测没有可证实的边际 → 一律不买。
2. 错价集中在**奖池比锐市场便宜**的那一档：x ≥ 门限（现约 1.10）。
3. **x 不是越高越好**：门限 ~1.2 附近最稳；极端高 x（>1.4）多半是锐市场参考噪声，
   实测「按 x 降序挑最高那几条」连一张票都中不了（赢家诅咒）。**不要专门去挑极端高 x。**
4. 低赔档（x < 1.0，即奖池比锐市场还贵）长期亏更多 → 一律不买（你连看都不用看）。
5. 你的「我觉得这场会赢」**不是边际来源**：引擎会把你报的 p̂ 封顶在市场的 1.25 倍，
   并按因子历史把它压回去。**边际来自 x，不来自你的信心。**

## 引擎每天给你什么

- 一份「今日候选腿」：只有 gl=0 且某侧 x ≥ 门限的场次，每条已算好 x 与市场 p̂。
- 门限 θ、各档实测 y 与置信区间、**每注最少关数 m_star**（现约 4 关）。
- 资金与成本上限（注数 × 2 元）。

## 你只做三件事

1. **排序**：在候选腿里挑出你最愿意连乘的前 N 条（决定串长；从 m_star 起步，每注最多 9 关）。
2. **否决**：只允许**信息层面**的否决——伤停/阵容/盘口异动/信息滞后让"奖池便宜"不再成立。
   不许用"感觉"或"低赔更稳"当理由；每条否决都要写清是哪条事实。
3. **定串长与票型**：`M ≥ m_star`；默认 `N串1`。只有确认某 1~2 条腿"边际真实但胜率不高"、
   且成本放得下时才用 `N过(N−1)`（容错不提高每元期望，只降方差，别指望它救 ROI）。
   候选不足 m_star、或全部被否决 → **空仓**（空仓是合法且常见的结论）。

## 因子怎么用（本狗特有）

- **方向型因子**：只用于在候选腿**内部排序**或否决。归因必须写因子清单里真实存在的名字——
  引擎要按因子历史校准你的 p̂。
- **波动型因子**：只当**风险提示**（可能爆冷的场次少押/不押）。它不产生方向、也不作为覆盖/多选依据；
  实测波动路径没有可证实的边际，别把它当选腿理由。
- 不许为了"用上某个因子"去凑腿。

## 纪律

- 一场最多一条腿；同一天同一场不重复买；**只买候选里的腿**。
- 默认单选；多选（2~3 个方向）会把该腿边际拉回市场均值，没有"每个方向都有边际"的证据就不多选。
- 出票前写清「为什么这几条腿值得连乘、每条 x 多少、串长多少、估 ROI 多少」；算不出 > 0 就不出票。
- 本狗是**沙盒验证版**：回放验证通过、人工转正后才上 live。
```

## 二、prompt build 怎么 run（有了账本先验之后）

### 现在的管线 vs 建议的管线

| | 现在 | 建议（账本版） |
|---|---|---|
| 候选来源 | stage1 对**当天所有场次**做逐场 LLM 初筛（30~100 场） | **stage0 引擎**：账本 → θ/m_star，从缓存直接筛出 `gl=0 且某侧 x≥θ` 的场次（实测 **13.2 腿/天**，44 天样本） |
| 候选呈现 | league/让球线/赔率 + stage1 初判 + 市场 p̂ | 同上，但**每条已由引擎算好 x 并标注**（`x=1.32 ✅`／`x=0.95 ⛔`），非候选场次**不进 prompt** |
| 任务 | stage1 两步（先方向、后波动）→ stage2 自由选腿+p̂+票型 | **stage2'：只能在候选里排序/否决/定串长**；p̂ 默认取市场值（微调会被封顶+校准） |
| 引擎复核 | 边际/护栏/ROI 门 | 加两道硬门：腿池门（gl + x≥θ）、关数门（M≥m_star） |

**给 LLM 的确定性事实**（账本产物，直接写进 prompt）：

- 今日门限 `θ`、`m_star`、来源（`ledger` / `config_default`）；
- 各档 `y` 与 95%CI（例如 `gl0 x≥1.1: n=737 y=1.286 [1.138,1.434]`）；
- 今日候选腿表（每条：side、x、北单赔率、市场 p̂、数据段）；
- 资金/成本上限、注数与关数的关系（注数 × 2 元 ≤ 预算）。

**LLM 的职责因此收缩为**：在这张表里排个序、给否决理由、定串长与票型。它不再需要"发现场次"。

## 三、stage1 + stage2 还适用吗？

三句话结论：

1. **stage2 的核心假设已经不成立。** 它假设"LLM 能找到市场没定价的边际（p̂ > 市场）"。
   实测 + 封顶（≤1.25×市场）+ `k_f` 校准说明：**LLM 的 p̂ 不能作为边际来源**（缩放不能创造边际），
   边际来自 x 档。所以 stage2 应从「全权选腿」降级为「在候选里排序 / 否决 / 定串长」。
2. **stage1 的两步过时一半。**
   - 方向步：输出 H/D/A「选哪一侧」——现在**侧由 x 决定**（账本按侧算 x），推荐值冗余；
     保留价值只剩「事实核验 + 因子归因」。
   - 波动步：输出「高波动」原本用来决定**全包/多选**。flex 下多选已被压低，且实测波动路径
     **不产生可证实的边际**（不进 x）→ 这一步现在既不产生边际，也只留下很弱的统计价值。
3. **建议形态**：`stage0（引擎账本，确定性） → stage1'（只对 gate 候选做核验+归因，可选） → stage2'（排序/否决/定串长）`。
   同时**必须加一个 0-LLM 对照臂**来判断 LLM 到底有没有增量：如果"按 x 排序取前 N"的规则票
   不输给人设臂，那 stage1/stage2 就该整体退役（省成本、少一层不确定性）。

## 六、0-LLM 规则臂基线（已跑，2026-07-01 ~ 09-09）

脚本 `scripts/rule_arm_backtest.py`（报告 `docs/rule_arm_report.md`，数据 `docs/rule_arm_result.json`）。
条件：只做 gl0、x ≥ θ（按天取账本）、每场一腿、每天 1 票 2 元、票型 `N串1`。
可用天数 ≈ 30~35 天（**受开奖 SP 覆盖限制**），合格腿池每天中位 11 条。

| N（串长） | 票数 | 腿级 y（95%CI） | 期望中票 | 实际路径 ROI | 池内随机 bootstrap 均值 ROI | 盈利概率 |
|---|---|---|---|---|---|---|
| 2 | 4（多数被关数门拦） | 2.05 [0.81,3.29] n=8 | 1.00 | +13% | +23% | 61% |
| 3 | 18 | 1.88 [1.40,2.36] n=54 | 0.91 | −100% | +77% | 64% |
| 4 | 30 | 1.40 [1.04,1.75] n=120 | 0.19 | −100% | +163% | 50% |
| 9 | 25 | 1.26 [1.01,1.50] n=225 | 0.00 | −100% | +586% | 0% |

### 三条设计结论（重要）

1. **x 门是边际的来源**：同样随机选腿，不过 x 门的对照组 ROI 为 **−14% ~ −73%**；过门后为正。
2. **在 x 上"择优"是有害的**：按 x 降序取前 N 的实现，35 张票 0 中（腿级 y 也低于池子平均）——
   在带噪声的比率上做选择 = 赢家诅咒。**规则臂默认改成"池内按日种子随机取 N 条"**，
   并在人设里写明"不要专门挑极端高 x"。
3. **验证窗口与关数门冲突**：账本用 CI 下界推出的 `m_star≈4`，但 30~35 天窗口里
   4 关票的期望中票数只有 **0.19 张**（9 关 ≈ 0）→ **票级"中没中"在这个窗口里说明不了任何事**。
   所以验证的主口径必须是**腿级 y 与置信区间**（引擎会给），或者把窗口拉长；
   N=2~3 的票级观测才有可读性（期望中票 ≈1 张/18 票）。
