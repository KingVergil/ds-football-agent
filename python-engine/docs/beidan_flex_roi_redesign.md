> 2026-09-11 ｜ 关联：`docs/bc狗_串关人设现状.md`（现状调查，本文修正其中 2 处结论）

## 0. 一句话

票型不再由配置写死：**LLM 给「腿集」（每腿 1~3 个方向 + 自估概率），引擎只做护栏与北单返奖数学**
（v̂ = p̂×赔率、Πv̂ > 1/0.65、注数/成本/资金占比），达不到正期望就空仓——包括"求稳买短串"这种负期望组合。

## 1. 北单返奖数学（用 1764 场真实开奖样本校准过）

```
中奖奖金 = 每注 2 元 × Π(开奖SP) × 0.65          ← 0.65 只乘一次，与串长无关
单注毛额 > 10000 元 → 按全额缴 20% 个税          ← 10000~12500 是净亏区
单腿边际 v̂ = p̂ × 赛前赔率        （p̂ = 你估的真概率）
整票 ROI   = 0.65 × Π v̂ − 1                      ← 打平需 Π v̂ > 1.538
```

**关于"65% 是否重复计一次"的实测结论（重要）**：统计 `data/beidan/*.json` 里 1764 场
「三路赛前赔率齐全且有开奖」的样本：

| 量 | 中位 | 解读 |
|---|---|---|
| Σ(1/赛前赔率) | **1.002** | 赛前赔率是**公平赔率**，不含抽水 |
| 开奖SP / 胜方赛前赔率 | 1.004 | 开奖 SP ≈ 赛前赔率（不是打折后的价） |

→ 抽水（65%）**只在结算时乘一次**，`beidan_settlement.py` 的公式正确；`p̂ = 市场共识` 时 v̂ ≈ 1.000。
（曾怀疑 beidan 赔率已内含 65%、结算再乘一次是双抽水，被这批样本排除；`BEIDAN_ODDS_FACTOR=0.68`
只用于「北单三路赔率不全时拿 Pinnacle 欧赔兜底」的换算。）

**打平所需每腿边际**（`_breakeven_table()` 由代码生成，人设/引擎同源）：

| 串长 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 10 |
|---|---|---|---|---|---|---|---|---|
| 每腿最低 v̂ | 1.240 | 1.154 | 1.114 | 1.090 | 1.074 | 1.063 | 1.055 | 1.044 |

→ **低串不是"稳"，而是要求单腿边际高到不可能（2串1 要 +24%/腿）**；正期望只能靠多条真有边际的腿连乘。
用户"北单模式还是会选择低串（roi 绝对要亏）"的判断在数学上成立，本文把它写进了人设与代码门。

**现状战绩反推**：15 票实际返奖 42.2% → `Π v̂ = 0.422/0.65 = 0.649` → 平均每腿 **v̂ ≈ 0.95**；
若 5 条全包腿按中性 1.0 计，3 条胆腿 v̂ ≈ 0.87（比市场差 13%）。**问题在胆腿没有边际，不在包太多。**

### 1.1 官方机制核对（奖池型浮动返奖）

官方口径：`单注奖金 = 2元 × 65% × SP1 × SP2 × …`，其中 `开奖SP = 单场总投注 ÷ 猜中该结果的投注额`
（奖池按 65% 分给猜中者；过关时本金+上一关奖金滚入下一关奖池，最终=本金×Π各场SP）。

代码逐项对应：`UNIT_STAKE=2.0`、`BEIDAN_RETURN_RATE=0.65`（`beidan_settlement.py` 的
`settle_parlay_combo`，**只乘一次**）、SP 取官方赛后 `spvalue`（`_fetch_beidan_results`/`beidan_sp`）、
取消/延期腿按 `VOID_SP=1.0` 滚过（等价"本金原额进下一关"）、全取消则退本金不乘 0.65。✔ 全部一致。

两个由此推出的、之前没写进口径的事实：

**(a) 赔率 = 资金占比的倒数 → "公平赔率"就是奖池快照。**
实测 2102 场 `Σ(1/赛前赔率)` 中位 **1.0018**（p10 1.0009 / p90 1.0028），正是 `Σ_s f_s = 1` 的归一化 →
赛前赔率不是庄家盘（无水位），而是**该场当时的奖池资金占比快照 1/f**。所以
`v̂ = p̂ × 赔率 = p̂ / f`：**edge 的唯一来源是"你的概率高于同池玩家的资金占比"**，
不是"打得过庄家的抽水"（抽水是固定 35%，谁都躲不掉）。这也解释了为什么"跟低水热门"永远没边际——
低水意味着 f 大，你需要在 f 已经很大的地方还要比它更看好。

**(b) 开奖 SP 是赛后定的，不是下注时的价 → 必须加漂移安全垫。**
实测 1531 场「开奖SP ÷ 胜方赛前赔率」：中位 1.008、p10 **0.849**、p90 **1.208**，
18.6% 的场次最终 SP 比下注时低 10% 以上。单腿对数漂移 σ≈0.13，n 腿乘积 σ≈σ√n。
于是出票线不再是裸打平线 1.538，而是：

```
出票线(n) = (1/0.65) × exp(z · σ · √n)      z=0.674(p25), σ=0.13
  2腿 1.741 | 3腿 1.791 | 5腿 1.871 | 8腿 1.971
```

配置项 `sp_drift_sigma` / `safety_z` 可调；显式写 `min_ticket_v` 则跳过安全垫（给回测做对照）。
**卡着 1.538 出票 = 赌漂移不反向**，这是奖池型玩法的结构性风险，已写进引擎门与人设。

成本上限之外的第二个纪律：单注毛额 = 2×ΠSP×0.65，**10000 元断崖** ⇒ 单注 SP 连乘要么 ≤7692、要么 ≥9615。

## 2. flex 模式（已上线）

### 2.1 决策权划分

| 层 | 负责 |
|---|---|
| LLM（人设驱动） | 今天买哪几场；每场选哪些方向（1~3 个）；每个方向的 p̂；腿的顺序（强→弱） |
| 引擎 | v̂ / Πv̂ / ROI 计算；剔「无边际」腿；腿数/注数/成本/资金占比护栏；Πv̂ ≤ 1/0.65 → 空仓；组票落盘 |

引擎**不再**决定串长、不再要求"3 胆 5 包"，也**取消了 "单选<3 → 整票拒绝" 的硬门槛**
（那是 09-04 起 26% 空仓的直接放大器）：现在是「有几条正边际的腿就买几腿，不够 2 腿就空仓」。

### 2.2 配置（`data/roles/bc狗/parlay.json`）

```json
{ "mode": "flex", "min_legs": 2, "max_legs": 8, "max_per_leg": 3,
  "max_combos": 128, "max_stake_pct": 3.0, "min_leg_v": 1.0 }
```

| 键 | 语义 |
|---|---|
| `mode` | `flex` = 腿集驱动；缺省/`legacy` = 老模板（3胆+5包），**其它北单狗不受影响** |
| `min_legs` / `max_legs` | 腿数区间；不足 `min_legs` → 空仓 |
| `max_per_leg` | 单腿最多选几个方向 |
| `max_combos` | 注数上限（成本 = 2 元 × 注数） |
| `max_stake_pct` | 单票成本 ≤ 资金该百分比（当前 298 元 → 预算 8.95 元 → 最多 4 注） |
| `min_leg_v` | 单腿 v̂ 下限；低于它的腿直接剔除（"无边际 = 不买"） |
| `min_ticket_v` | 整票 Πv̂ 下限；缺省 = 打平线 × SP 漂移安全垫（见 §1.1b） |
| `sp_drift_sigma` / `safety_z` | 漂移安全垫参数（默认 0.13 / 0.674 → 2腿 1.741、3腿 1.791） |
| `market_allowance` | LLM 自报 p̂ 相对市场 p̂ 的封顶倍数（默认 1.25） |
| `require_market_p` | true = 拿不到市场参考的场次不进票（默认 false） |

护栏修剪顺序：**先剔无边际腿 → 再按腿数/注数/成本上限从尾部删**（尾部 = LLM 排序里最弱的腿），
每次剔除都打印理由，并记进订单的 `flex.dropped`。

### 2.3 落盘与可观测

- 订单腿里新增 `p_hat`（每方向概率）、`odds_all`（整场三路赔率）、`leg_v`（该腿边际）；
  订单顶层新增 `flex: {combos, cost, ticket_v, roi, budget, dropped[]}`。
  **这些就是方向路径的校准样本**（p̂ vs 开奖 actual/SP），下一阶段直接用。
- 每次 analyze 打印一行计划：`🧾 flex 票 N串1 | 注数 | 成本（资金 x%） | Πv̂ | 估 ROI | 各腿 v̂`；
  空仓时打印具体原因（腿数不足 / Πv̂ ≤ 打平线）。
- 多波次回放的返回值里，每波的 `waves[i].flex` 与合并结果的 `flex` 都带计划元数据。

### 2.4 行为变化对比

| 场景 | 旧（模板 + 硬门槛） | 新（flex） |
|---|---|---|
| 当天只有 2 条真站得住的腿 | **整票拒绝 → 空仓** | 出 2串1（只要 Πv̂ > 1.538） |
| 当天有 8 条腿但只有 2 条有边际 | 硬凑 8 腿，5 条全包摊平命中率 | 只买那 2 条 |
| LLM 想买 3 条双选腿 | `cover_picks` 配置说了算，多选语义是"防冷" | 腿集自己带 picks，多选 = 同时看好这些方向 |
| LLM 报的 Πv̂ = 1.32（+15%/腿 × 2） | 出票，事后才知道亏 | **不出票**，打印"Πv̂ ≤ 打平线（估 ROI −14%）" |
| 资金 298 元 | 仍可下 486 元/票（`capital ≥ cost` 就放行） | 成本 ≤ 资金 3%（≈8.95 元） |

### 2.5 phase 2（已上线）：引擎侧市场 p̂ 封顶

引擎自己从**与北单同一盘口**的锐市场取概率，用来给 LLM 的 p̂ 封顶（"融合"里的市场那一半）：

| goal_line | 参考来源 | 覆盖率（实测） |
|---|---|---|
| 0（北单就是 1X2） | `欧盘:Pinnacle` 最后一行（去水）；退化用必发「价位(主/和/客)」 | 高（近期样本 68/101） |
| ≠ 0 | 公平盘段「平均欧盘胜/平/负(<line>)」，**<line> 必须 == goal_line** | 33/101（其余盘口不一致 → 无参考） |

规则：`p_used = min(p_LLM, p_mkt × market_allowance)`（`market_allowance` 默认 **1.25**）——
LLM 最多可以比锐市场看多 25%，超出部分引擎直接砍掉，v̂/Πv̂/ROI 全部用砍完的值算。
`require_market_p=true` 时，拿不到市场参考的场次直接剔除（默认 false，但会在计划行里计数）。

实测（真实切片 + 假 LLM）：

| 场景 | 结果 |
|---|---|
| 假 LLM 自报每腿 v̂=2.0（喊高） | 3 侧全被砍到 v̂=1.25 → Πv̂=1.953（+27%），而不是 8.0（+420%） |
| 假 LLM 自报每腿 v̂=1.22，市场持平 | 不砍 → Πv̂=1.816（+18%）出票 |
| 无市场参考 + `require_market_p` | 全剔 → 空仓 |

**顺带修掉一个真 bug**：`_beidan_odds` 的 Pinnacle 兜底原先乘 `BEIDAN_ODDS_FACTOR=0.68`
（假设 65% 已含在北单赔率里）。但 2102 场实测 `Σ(1/北单赔率)` 中位 **1.002**、开奖SP≈赛前赔率 →
北单赔率是公平赔率，兜底应「去水成公平赔率」（乘 ≈1.04），不是乘 0.68。
旧口径让**所有走兜底的场次赔率系统性低 ~32%**（历史回放里大量场次的三路赔率已随开奖清空，正好走这条路），
表现为 v̂ 被压低、回测比实盘更容易空仓。已改为去水兜底。

### 2.6 已知代价与风险

1. **ROI 门依赖 LLM 自报的 p̂**：模型若系统性高估，门会失效。缓解见 §4 的 phase 2（引擎用市场 p̂ 交叉校验）。
2. 规则兜底（LLM 失败时）产出的腿没有 p̂ → 引擎判"无边际" → flex 下**空仓而不是硬出票**（刻意）。
3. `stage2_flex` 会把候选场次的数据段再发一遍（每场 ~350 token 上限），单轮 token 比旧 stage2a 高。
4. 目前只改了 LLM 决策路径；`analyze(..., max_picks=...)`/`backtest()` 的规则路径仍是旧行为。

### 2.7 串关结算：一票否决（一关错就不算组合）

用户口径：「只要有一关是错的，就先拒掉，不要计算所有组合的结果。」

**数学依据**：串关要求每腿各中一个方向。某腿的 `picks` 里**一个都没中**时，任何组合都在这一腿断掉
→ 整票必不中，**与其它腿是否开奖无关**。所以可以：

1. **提前判死**（`_judge_ticket_legs` 返回 `{"dead": True, "dead_leg": {...}}`）：
   已有腿确定零命中 → 立刻按「不中」结算（`return=0 / profit=-total_stake / push=False`），
   **不再等其它腿开奖**，也**不展开任何组合**；订单里留 `early_kill={lota_id,picks,actual}` 便于回查。
2. **只算活下来的组合**：没有必杀腿时，每条腿只保留命中的方向（走水腿保留全部），
   再展开笛卡尔积——未命中的组合必然派彩 0，展开它们纯属浪费（数学完全等价）。

**实测（8串1：7 腿三选 + 1 腿双选 = 4374 注，其中一腿必杀）**：

| | 旧做法 | 现在 |
|---|---|---|
| 一腿错时 | 遍历 4374 注逐个算派彩 | 腿级判死，**0 注** |
| 耗时 | 44.6 ms | **0.031 ms（~1440×）** |
| 结算时机 | 等所有腿都开奖 | **错一腿即结**，资金/挂单不再被占 |

顺带修掉一个潜伏 bug：`_judge_ticket_legs` 的默认 `diag` 写成 `{"runs": []}`（应为 `0`），
只有"直接调用且不传 diag"才会炸（线上 caller 一直传 `runs: 0`，所以没暴露）。

### 2.8 上限口径与票型自由度（2026-09-11 首版 · 2026-09-12 按用户口径修订）

用户口径（首版）：「结算模式的自由度可以改，只限制最高 9 关。」
用户口径（修订，原文）：「**原来最高允许 9 串，实际上 12 场单选，容错 4，是允许的。**」

⇒ 「最高 9 关」限制的是**每一注的组合腿数 M**，不是**选场数 N**。容错票把 N 撑大的同时
把每注压回 9 关以内，所以 `12过8`（12 场单选、容错 4、每注 8 关、C(12,8)=495 注）合法。

| 项 | 现在 |
|---|---|
| 每注关数 | **M ≤ 9**（`BD_MAX_COMBO_LEGS`，`_valid_flex_ticket` 拦 M>9） |
| 容错额度 | **N − M ≤ 8**（`BD_MAX_TOLERANCE`） |
| 选场数 | **N ≤ PICK_N = 9 + 8 = 17**（`FLEX_DEFAULTS.max_legs=17`、`max_legs` 与 `PICK_N` 取 min） |
| 票型 | LLM 可给 `ticket`：`N串1`（每腿必中）或 **`N过M`**；校验 **N == 腿数、2 ≤ M ≤ 9、N−M ≤ 8**，不合法回落兜底票型 |
| 兜底票型 | `_default_ticket(n)`：n ≤ 9 → `n串1`；n > 9 → **`n过9`**（一注 9 关、容错 n−9），绝不返回非法票 |
| 注数/成本 | 按票型**精确**算：`注数 = Σ_S Πk_i`（S 取 C(N,M) 组合）、`期望 = Σ_S Π(k_i·v̂_i)` |
| ROI 门 | 等效 Πv̂ = 期望 / 注数（M=N 时即 Πv̂）；漂移安全垫按**每注关数 M** 取（M=2 →1.741、M=5 →1.871、M=8 →**1.971**、M=9 →**2.001**） |
| **容错保持型修剪** | 成本/注数护栏裁腿时**保持 t = N − M 不变**：9过8 裁到 8 腿 → **8过7**（不会退化成 8串1 把容错吃掉）；腿数少到放不下容错时（n − t < 2）才退化为 C(n,2) |
| 结算 | 一票否决的容错额度 = **N − M**（错腿数 > 额度才判死）；活组合只取"不含错腿"的子集；早杀时把 `early_kill_legs` 一起落盘（错腿明细可查） |
| 展示 | 容错票的 `sub_ticket` 用**完整票型**（`12过8`），不再显示成 `8串1` 把 N 藏掉；订单 `pick` = `12过8 x495注` |

**实测（真实代码路径）**：

| 场景 | 结果 |
|---|---|
| 请求 `9过8`、资金 533.4 元（3% = 16 元） | 裁到 8 腿 → **`8过7`**、8 注、16 元、`ticket_changed=True` |
| 请求 `12过8`、资金 40000 元、`max_combos=1024`/`5%` | 原样 **`12过8`**、495 注、990 元、等效 Πv̂ 4.30 > 线 1.97 |
| 请求 `12过8`、`max_combos=128` | 按 t=4 裁到 9 腿 → **`9过5`**、C(9,4)=126 注 |
| 请求 `12过8`、资金 298 元（10% = 29.8 元） | 裁到 5 腿 → **`5过2`**、10 注、20 元 |
| 无票型的 12 腿 | 兜底 **`12过9`**（容错 3） |
| 无票型的 18 腿 | `_flex_slip` 直接拒票（超 `PICK_N=17`） |
| 结算 `8过7` 错 1 腿 | **不**触发一票否决：7 条活腿的 1 注派彩（2 元 × 2^7 × 0.65 = 166.4 元），其余 7 注为 0 |
| 结算 `8过7` 错 2 腿 | `2 > 容错 1` → 一票否决，**不等其余 6 腿开奖**、不算 C(8,7) 注 |
| 结算 `12过8` 错 4 腿 | 容错内 → 活注 1 注派彩（2 元 × 2^8 × 0.65 = 332.8 元），成本 990 元 |
| 端到端（真实切片 2026-07-18，stub stage2 给 12 腿 + `12过8`） | 两波各落 1 张 `12过8`（495 注 / 990 元，资金 20000 → 4.95%）→ 结算错 4 腿：`hit=True`、派彩 332.8 元、无早杀；护栏耗时最坏 181 ms（17腿×17过9） |

`parlay.json`（bc狗）相应上调：`max_legs 9 → 17`、`max_combos 128 → 512`、
`max_stake_pct 3 → 10`（原 3% 在 298 元资金下只有 8.95 元，连 `9过8` 的 18 元都放不下，
容错票等于被成本护栏锁死；10% 是"允许容错"能落地的最低档，仍受 `max_combos` 二次约束）。

**人设侧**：新增「票型：`N串1` 还是 `N过M`——也由你定」一节，写明
① 每注期望 ROI = `0.65 × (Σ_{M 子集} Πv̂ / C(N,M)) − 1 ≈ 0.65·v̂^M − 1`，**打平门槛由 M 决定**；

**重设计方向（与 flex 天然衔接）**

1. **方向路径 = 校准 p̂ → edge**：flex 每腿已经落盘 `p_hat/leg_v` + 开奖 `actual/sp`。
   结算时按 `(factor, side)` 累加样本 → 得到「该因子给出的 p̂ 是否校准（reliability/分桶命中率）」→
   下一轮用校准后的 p̂ 生成 v̂。**这才是能提高期望的飞轮**，而不是统计因子名字的历史命中率。
2. **波动路径 = SP 分布 vs 成本线**：波动因子的产出应该是「覆盖这条腿时，开奖 SP 分布的
   `p(SP > 成本线 / 0.65)`、`E[SP] / 覆盖成本`」，用**赛前特征**（离散/盘口/水位）分层抽样归纳，
   候选样本**不得**按开奖 SP 排序、不得带 `actual`（修 G3/G6）。
3. **字段分路径**：`history[]` 拆两套（方向 `{pick, actual, hit, return_ratio}` / 波动
   `{sp, cover_cost, cover_payout, return_ratio}`，波动废弃 `hit`）；因子条目加 `kind/scope/unit_cost/
   sample_kind`；`n` 拆成 `n_window/n_decided/n_observation`。
4. **生命周期**：波动因子要有自己的晋升/休眠/退役（`p(SP>线)` 长期为 0 → 退役；SP 分布无区分度 → 休眠）。
5. **回填工具**：一次性回填 `type` 与历史 `sp`；不可回填的样本显式排除（而不是走错公式）。

### 4.3 已落地（3a）：方向路径校准 p̂

**数据链**：flex 腿集 JSON 现在必须给 `factors`（只接受因子清单里出现过的名字，防幻觉）；
结算时把每条腿的 `(p̂_s, 结果)` 写进角色目录的 `memory/p_calibration.json`，按路径分开统计：

```
k_f = (Σ hit + a) / (Σ p̂ + a)          a = 2（先验强度；样本少时向 1 收缩）
一条腿的 k = 各归因因子 k 的最小值（最保守）；无因子/无样本 → 1.000（中性）
```

应用顺序（`_flex_leg`）：自报 p̂ → **× k_f** → 市场封顶 `min(p, p_mkt × market_allowance)`。
作用：某因子过去"声称 60% 实际只中 40%"，下一轮它支持的概率就被压低 → v̂ 变小 →
该腿可能跌出 `min_leg_v`，或让整票过不了出票线。**这才算"用结果检验声称概率"的闭环。**

沙箱回放时校准文件落在沙箱 `memory/` 下 → 回放自己累积、不污染线上角色。

**实测（真实切片 + 假 LLM 故意喊 0.95，跨两天）**

| | 第 1 天 2026-08-19 | 第 2 天 2026-08-20 |
|---|---|---|
| analyze | 3 腿各声称 0.95 → 市场封顶到 0.678/0.642/0.427（v̂=1.25）→ 出票 Πv̂=1.953 | 同左，出票 Πv̂=3.616 |
| settle | 结果未齐 → 该票挂到次日 | 结算 1 票（3 腿），**🎯 概率校准记入 3 个 (p̂, 结果) 对** |
| 校准库 | — | `k=0.874`（声称合计 1.43 / 实际命中 1.00 → (1+2)/(1.43+2)） |

**顺序上的一个事实**：`market_allowance=1.25` 通常先于校准生效——模型喊 0.95 时基本都被
封顶到市场允许的上限，此时 k 再低也压不动（值已是上限）。所以校准目前主要作用在**模型报得
较保守（低于封顶线）**的腿上；等校准样本攒够、确认模型系统性高估后，可以收紧
`market_allowance` 让校准接管主防线。

### 4.4 已落地（3b）：波动路径重写（赛前分层抽样 + 生命周期）

**G6｜候选不再由开奖 SP 决定。** 原来波动路径的候选是"按开奖 SP 降序取 TOP-N"，
归纳出的因子只会描述事后赢家、学不到区分度。现在：

| 环节 | 现在 | 之前 |

| 已结算全包腿 | 按 **赛前离散**（`tools.prematch_dispersion`：离散指数序列首行→末行的最大相对变动）分层排序，标 `【赛前离散低/中/高｜离散x.xx】` | 按开奖 SP 降序 + 标 `【高波动全包候选 SP=x】` |

**G4｜波动因子终于有生命周期**，而且判据是**粗筛口径**（不是精确计算）：

| 情况 | 建议 |
|---|---|

### 4.6 波动路径的定位（用户口径，2026-09-11 修订）

> 「这个因子的主要产出是 LLM……我并不需要一个很准确的计算结果，我只需要大概过滤
> 一天内哪些比赛可以出现高波动结果。」

据此把波动路径的接口定成**粗筛**，不做精确统计：

| 层 | 产出 | 形式 |
|---|---|---|
| LLM 选腿（flex） | 今天哪些场次「像会出高波动」→ 决定覆盖/多选 | 提示词里明确写「把波动因子当粗筛；不要用精确概率算覆盖划不划算」 |
| 因子文本（进 prompt） | `标记 29 场中 4 场高波动（14%）vs 当日基线 12%（+2pp）` | 一个比例 + 一个差值，无分布运算 |
| 因子生命周期 | 有筛选力 / 没筛选力 | 差值 pp（≥10pp 保留 / ≤0 退役 / 中间观察）+ 样本量，见 §4.4 |
| 引擎 | 覆盖腿的成本/注数/资金护栏 + 整票 ROI 门 | 仍然是精确的（因为要花钱），但**概率由模型给、只被市场与校准封顶** |

**日级粗筛的数据流（关键：统计对象是"标记过的所有场次"，不是只统计下过的腿）**

```
analyze/flex → stage1 对全部候选场次的因子归因
              └→ memory/screen_<day>.json   （lid → {因子, stage1 推荐}）
settle       → _accumulate_vol_screen(day)
              ├ 当日每场开奖 SP（含未下注场次）→ 高波动标签 = SP ≥ 4.615（覆盖成本线）
              ├ 当日基线 = 当日高波动场次占比（<5 场不给基线）
              └→ factor.screen = {n: 标记场次数, high: 其中高波动数, base_sum: Σ当日基线}
prompt       → factor_profile.vol_precision/vol_base/vol_edge → 粗筛文本 + 生命周期
```

⚠️ **为什么必须按"标记场次"而不是"下注腿"统计**：下过的腿本来就是精挑的，用它算出来
`命中高波动率 100% vs 基线 3%（+97pp）`；换成当日标记的全部 29 场（含没下注的）后是
`14% vs 12%（+2pp）`——**选择偏差把筛选力夸大了 ~95pp**。所以显式留档 stage1 归因
（`screen_<day>.json`）并把优先口径放在它上面。
