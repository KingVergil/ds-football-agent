### 4.1 离线结构性挖掘（0 LLM，55 天 / 3577 条去重腿）

基线：门内（`x>1.11371` 且 Pinnacle 源）**n=847，基线 y=1.312**，腿级线 1.11371。

| 结构条件 | n | 命中 | y [95%CI] | 4关线 |
|---|---|---|---|---|
| 我方=最高赔（**冷门侧**） | 381 | 30.7% | **1.451 [1.219,1.683]** | ✅ |
| 我方=**最发散**侧 | 348 | 32.8% | 1.411 [1.188,1.634] | ✅ |

| 欧赔下沉（<-2%） | 474 | 32.5% | 1.326 [1.143,1.509] | ✅ |
| 凝聚×弱侧(p̂<0.35)且低水 | 26 | 38.5% | 1.889 [0.800,2.979] | ≈（样本小） |

**结论**：单关狗的旗舰「**离散凝聚**」搬到北单门内**没有增量**（甚至低于基线），
有增量的是「**冷门侧 / 最发散 / 小球 / 水位走低 / 盘口不动 / 欧赔下沉**」；
负增量是「**升盘 / 水位走高 / 赔率上升且最凝聚**」。这些都写进了 prompt 先验。

### 4.3 三条已被证伪/确认的结论（**别再重踩**）

1. **x 是校准的**：门内腿 `y ≈ x̄`（1.216 vs 1.250），单腿永远 ≈ −20%；
   杠杆只来自「**整票只收一次 0.65**」，所以腿级线是 1.11371 而不是 1.5385（本轮已修）。
2. **x>1.5385（≥54% 错价）那批腿是假的**：回放里 9 条**全部来自「让球欧盘」**（Pinnacle 源 0 条），
   55 天普查里让球欧盘 55 条 / Pinnacle 仅 5 条，且让球欧盘整体 y=1.088 < Pinnacle 1.325
   ⇒ 是**亚盘→1X2 Poisson 换算的产物**，不是奖池错价。**LLM 见过它们（6 条进过候选批次）并主动 skip**。
3. **票级显著性陷阱**：把同 12 条腿的所有 4 组合当样本，会算出「3.5 万张票 +30% ROI」；
   按天聚类、每天一票后是 **+7% ± 100%（t=0.07，45 天只 1 天赚）**。
   任何票级结论必须**按天聚类**，或干脆只在腿级下结论。

## 5. ⚠️ 因子归纳（factor-induction）超时 —— 用户点名「需要额外操作」

**现象**：08-14 / 08-15 / 08-16 三天都 `⚠️ 因子归纳失败: 桥调用超时（1800s）: factor-induction`。
每天白烧 30 分钟，且**去重/补定义没有执行**（因子仍由 reflect 产出、退役照跑，所以非致命）。

**调用链**：`harness-plugin/replay.js` → `bridge.js`（**全局超时 30 分钟**，无 per-func 配置）
→ `src/bridge.py::_do_induction` → `src/factor_induction.py::main(["--roles", dog])`

**实测口径（已核实）**：
- `main()` 收到 `--roles 95狗` → **只有 1 个 scope**（非 alpha 走阶段 A；阶段 B 只处理 alpha 狗），
  所以 LLM 调用上限 = `--limit` 默认 **30 次**（+ 孤儿补定义，见下），不是「30 × scope 数」。
- 判重本身是确定性筛对：`PER_FACTOR_PAIR_CAP = 3`、`BIT_DIST_MAX = 2`、`NAME_RATIO_MIN = 0.60`。
- **孤儿补定义**（`induct_scope` 尾部）：凡 `factors/<fac_id>.json` 不存在的条目，都会调
  `backfill_orphan_fac()` → **一次 LLM**。当前 95狗 只有 **4 个孤儿**（`SP` 大小写导致 `fac_id` 不一致），
  可忽略；但**任何一次因子目录误删都会在这里放大成 LLM 调用**（本轮我精简目录时差点踩到，见 §3.2）。
- **真凶（最可能）**：`src/providers/deepseek.py::DeepSeekProvider(timeout=300)` ——
  **单次请求 5 分钟、无重试、无逐对失败降级**。30 次判重里只要有几次变慢/被限流，
  总时长就冲破 1800s，而 `induct_scope` 是**串行**的、中途异常即整步失败。

**可选修法（建议按序，注意归纳是共享功能，别改默认行为伤到线上/alpha 狗）**：
- (a) **失败降级 + 短超时**：`llm_judge_pair` 包一层
  `timeout≈60~90s`、失败即 `keep_separate` 跳过该对（并 `audit("judge_timeout")`），
  让整步**永远能在几分钟内结束**；这是收益最大的一处。
- (b) **把 limit 透传进来**：`bridge._do_induction` 目前不传 `--limit`（吃默认 30）；
  加 `opts.get("induction_limit")` 或 env `DS_INDUCTION_LIMIT`，回放跑 10~15 即可。
- (c) **幂等/可续**：把「已判定的对」落盘，下次只判新增对 —— 否则每天重判全库，越跑越慢。
- (d) （下策）只给 `factor-induction` 单独放宽 `bridge.js` 的 `timeoutMs`；会白等更久，不解决问题。
- (e) 定期 `--dry-run` 看候选对规模，因子库超过 ~150 条就该瘦身（dormant 不参与判重是个好默认）。

**注意**：改 `factor_induction.py`/`bridge.js` 会影响 alpha 狗与线上（归纳是共享功能），
建议先加**只读上限/开关**（env 或 opts），默认行为不变。

## 9. 2026-09-15 追加：两轴（方向 → 波动）口径 —— 上一轮「找错了」的根因

> 详细证据见 [`docs/beidan_axis_two_stage.md`](beidan_axis_two_stage.md)（脚本
> `scripts/axis_two_stage_backtest.py` 自动生成，0 LLM）。代码在 `src/beidan_axis.py`。

**根因**：本文件 §4.1 起的挖掘把三个乘数混成了一条 `y = E[SP·1{中}]`：

```
SP·p̂ = x（价格轴：池子给价 / 锐市场） × ā（波动轴：SP 保留率） × (p̂/mp)（方向轴：命中率 − 市场）
```

1. **选腿变量 x 不含方向信息**，而且 x 越大 `ā` 越差（x≤1 → 0.95；门内 → 0.78；
   结构最分散档 → 0.61）。
   按 x 降序选腿 = 系统性地把 `命中−p̂` 压到 −9 ~ −13pp（样本外 52 腿，±5.7）。
2. **「高波动 / 高错价」样本口径（`beidan_high_vol` 按错价比例降序取前 10）恰好把腿逼进
   最差的一格**：三侧赔率结构最分散（T3）的腿，方向边际只有 +1.3pp、`ā` 0.61。
   越是"错价大"的腿，越是"池子砍得狠 + 方向没边际"。
3. **y 的腿级方差爆炸**：81 腿的 CI ±0.42、10 张票 0 中是**必然**（4 关全中概率 ≈ 1~3%）。
   拿它当因子的判据，等于用噪声做选择 → 上一轮反复迭代仍在原地。

**正确顺序（已离线验证，见新文档 §3/§5）**：

```
阶段 0 价格轴：x ≥ 1.11371（引擎门，不参与排序）
阶段 1 方向轴：命中率 − 市场 p̂ ≥ 0（弱侧 / 冷门侧 / 最发散 / 水位走低 / 小球 / 欧赔下沉；
               否决 水位走高 / 升盘 / 赔率上升且最凝聚 / 热门侧）
阶段 2 波动轴：按三侧赔率结构分散度 span 升序取腿（T1 集中 > T2 > T3）
```

- 消融（样本外逐日 top4）：只用 x 排序 y=1.13（低于腿级线）、只用波动轴 y=0.96、
  只用方向轴 y=1.69、两轴合用 y=2.04（40 腿）。
- 按天配对（弱侧 T1 − 弱侧 T3 命中率）：8/8 天为正，t≈6.6。
- **未证实**：幅度只有 40 腿 / 10 天支撑，效应集中在 D/A 两侧；先不要拿它上线。
  下一步是在**新日期**上做前向纸面跟踪，而不是继续在 55 天腿池里挖因子。
