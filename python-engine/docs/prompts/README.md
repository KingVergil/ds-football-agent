# prompt dump（step-by-step review 用）

`dump_prompts` 只**构建** prompt、**不调用 LLM**（用一个只记录不请求的 provider 桩，
并让 stage2 返回空腿集 → 引擎判定空仓）。用于逐轮人工 review prompt 内容。

## 生成

```bash
# 单日（默认输出到 docs/prompts/）
python3 -m src.beidan_parlay_dog prompt 2026-07-11 --user bcl狗 --out docs/prompts
# 或脚本里：dog.dump_prompts("2026-07-11", out_dir="docs/prompts")
```

每份 = `<狗>_<日期>_<stage>_<序号>.md`，正文含 `## SYSTEM` / `## USER` 两段 + 字符/token 统计。

# 2026-09-11 追加修正（用户 review 反馈）

## 1. "batch-1 是不是被切断了？" —— 没有切断，是段落顺序问题

审计证据（07-11 stage1 #1）：**18 场 / 126 个段落块（每场 7 段）**，末场段落齐全
（`discrete-odds → … → match-head`），文件末尾是收尾指令行
`逐场给出「同意/否决 + 归因」；只输出 JSON。` —— 说明 prompt 是完整的。

用户看到的"最后一段是 `[section:match-head]`"来自**旧的段落排序**：`FACTOR_SECTIONS`
故意把 `match-head` 排在最后，理由是"truncate 从尾部切，重要的离散/必发信号放前面"。
现在**全量不截断**，这个理由不成立了，因此改为：

```python
dm.get_sections(lid, slugs, source_order=True)   # 只在北单 stage1 打开
```

→ 每场段落顺序 = **原始 txt 的顺序**：`match-head → fair-odds → discrete-odds →
betfair-buysell → eu-odds-pinnacle → asian-handicap-pinnacle → over-under-crown`。
（其它狗默认 `source_order=False`，prompt 逐字节不变 = 隔离红线。）

## 2. stage2' 删除波动型因子块 + "多选/覆盖"话术

- 删除 `## 🛡️ 波动型因子（…决定覆盖/多选…）` 整块（新口径：波动因子不产生 x，只能用于否决）。
- 输出说明里的多选话术改为：**默认单选**（只买 x 最高的那一侧）；多选会把边际拉回市场均值，
  **没有证据支撑**，除非能写出"2~3 个方向都真有边际"的理由。
- 重跑后 stage2' 规模：**7669 字符 ≈ 3.4k tokens**，17 个章节；prompt 里仅剩的"波动型因子"
  一处在**人设**里（"只当风险提示"），保留。

# 2026-09-11 架构收尾：删掉 stage2（ticket_mode="rule"）

**结论（用户判断成立）**：stage2 的职责（填模板 / 定价 / 否决 / 排序）分别被「票型自由度 / 引擎 x / stage1 veto / 规则」吃掉，
两天实测它没有任何可观测增量（08-15：stage1 245 判断、67 veto、10 条打在可下注腿上；stage2 只是把剩余 ✅ 腿全取上组成 N串1）。

## 新链路

| 层 | 谁 | 做什么 |
|---|---|---|
| stage1（**唯一 LLM 阶段**，batch=20，全量数据） | LLM | 逐场：`推荐 / veto / factors`（+ 可选 `extra_picks`） |
| 组装 | **引擎规则** | ① 腿池 = `gl0` 且某侧 `x≥θ`；② **veto → 整场剔除**；③ 一条腿 = 该场所有过门侧（**自动双选/三选**）+ `extra_picks`（按被选侧平均 x 判门）；④ `x_cap=1.45` 排除极端尾部；⑤ `N=min(腿数,9)`、`N串1`；⑥ 关数门 + **成票判据锁死 x**（`Πx > 出票线`） |

配置（bcl狗 `parlay.json`）：`ticket_mode="rule"`、`gate_basis="x"`、`x_cap=1.45`。
