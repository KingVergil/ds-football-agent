# 交接文档 — DSH 插件重构 + 半交互回放（2026-08-18）

> 目的：换机继续开发用。记录这几轮改了什么、为什么、怎么验证、还剩什么。
> 代码根目录：`harness-plugin/`。宿主运行时包 `@deepseek-ai/*` 由 dsh 环境提供（本机 `npm` 未装，跑含宿主依赖的测试会报 `ERR_MODULE_NOT_FOUND`，属正常）。

---

## 1. 总体目标（用户诉求）

1. **User Role 整合 + 允许外置修改**：角色（狗）人设 / 资金 / 作用域集中管理，支持外部配置覆盖（不改代码）。
2. **无 LLM 固定工作流整合一块**：data_fetch、settle、下单、存储迁移、只读数据等。
3. **有 LLM 但 headless 的工作流整合一块**：settle-all、因子归纳/判重、reflect、factor-review、replay、分析。
4. **分析改造**：`data_fetch` 做成**单例**；分析改成**单狗 headless**（`ds_analyze_dog`），并行由父 agent 决定，不在工具里硬编码；**删除** `ds_analyze_all_parallel`。
5. **半交互 replay-run**（本轮重点）：按狗设定 + 日期范围回放，在固定周期允许用户接入——
   - 给「**下一轮因子归纳方向建议**」交用户编辑；或
   - 「**回到那一天的状态**」（rewind）；
   - 也允许「**一路到底**」的自动模式。

---

## 2. 模块结构（重构后）

`index.js` 从 ~1100 行单体 `apply()` 拆成"装配器"：解析配置 → 建核心服务（storage/dashboard/timers/system prompt）→ `resolveRoles()` → 按语义组注册工具。

| 文件 | 职责 |
|---|---|
| `tools/shared.js` | 公共工具函数：`KIND_DIR / LOOSE_OBJECT / readJson / readMatches / listKeys / normalizeFeature / findMatch / readSections / truncate / jsonRender` |
| `tools/roles.js` | 角色解析 + 角色工具：`resolveRoles(config, cacheDir)`（`dogs` 列表、`personaFor(dog)`、`scopeFor(dog)`、`personaDir`）；注册 `ds_persona_js / ds_memory_js / ds_capital_js` |
| `tools/deterministic.js` | 无 LLM 固定流：`ds_prepare_day / ds_settle_js / refresh_orders / submit_orders / fetch_scores / ds_settled_js / ds_replay_restore / ds_migrate_storage / ds_export_to_python / lota_matches / lota_match / lota_sections` |
| `tools/headless.js` | 有 LLM 的 headless 流：`ds_analyze_dog / ds_settle_all / ds_factor_flow / ds_replay / ds_reflect_js / ds_factor_review_js / ds_factor_dedup / ds_factor_induction` |

注册函数用统一 `deps` 对象注入依赖，签名干净。

## 3. 外置角色修改（config hook）

- `resolveRoles(config, cacheDir)` 统一决定 `dogs` 与 `personaFor/scopeFor`：
  - `config.roles`（内联覆盖人设/资金/作用域）优先；
  - 否则 `config.personaDir`（外置人设根目录）；
  - 再否则默认 `cacheDir/roles/<dog>/persona.md`。
- `reflect.js` 的 `readPersona(cacheDir, dog, personaDir)` 增加可选 `personaDir` 参数，默认 `join(cacheDir,"roles")`。
- 所有调用点（`fanout.js`、`replay.js`、`factorReview.js`）都已透传 `personaDir` / 人设覆盖。

## 4. data_fetch 单例 + 单狗分析

### 4.1 `dataflow.js` — `prepareDay` 单例
- 原逻辑重命名为 `prepareDayCore`；新 `prepareDay` 包装层提供：
  - **幂等缓存**：TTL 内复用已准备结果（live 有 TTL；replay 视为不变=长期）；
  - **在途去重**：并发同 key 调用共享同一个 Promise（`__prepareCache` / `__prepareInflight`）；
- 新增 `invalidatePreparedDay` 手动失效。

### 4.2 单狗分析 `ds_analyze_dog`
- **删除** `ds_analyze_all_parallel`。
- `fanout.js` 新增 `analyzeOneDog(ctx, opts)`：读已准备的 matches 快照 + 人设 → `runOneDog` 起**一个** subagent 分析单狗。
- `runOneDog` 的 `toolFilter` 改为 deny `ds_analyze_dog`（防递归）。
- `tools/headless.js` 的 `ds_analyze_dog` 调 `analyzeOneDog`，强调父 agent 先 `ds_prepare_day` 一次，再对每只狗并行调用（并行度由父 agent 决定）。
- 同步更新：`index.js` 的 `ANALYZE_FRAMEWORK_SECTION` 提示词与 `startScheduledJobs`（先 prepare 一次再逐狗分析）、`client.js`「⚡ 分析全部」按钮、`.dsh/skills/ds-agents-analyze-all/SKILL.md`、`docs/task_status.md`、`docs/workflow_tool_groups.md`。

## 5. 半交互 replay-run（本轮重点）

### 5.1 语义（对齐用户最终确认）
- **一路到底（默认）**：不传 `mode`/`interactive`，整段跑完出报告（行为与旧版一致）。
- **半交互**：`mode="interactive"`（或 `interactive=true`）→ 每个因子退役周期（`factor_review_every` 天）结束**暂停**，返回：
  - `status:"paused"`、`run_id`、`next_day`、`remaining_days`；
  - `direction_suggestion`：本周期退役/盈亏摘要生成的「下一轮因子归纳/退役方向建议」（启发式，LLM 可用则润色）；
  - `factor_reviews`、`trajectory_tail`、`checkpoints`。
- 续跑（`resume_run_id`，三选一，可组合）：
  | 意图 | 调用 |
  |---|---|
  | 采纳/编辑方向后继续 | `ds_replay(resume_run_id, induction_notes="<编辑后的方向>")` |
  | 回到某天状态重跑 | `ds_replay(resume_run_id, rewind_to="YYYY-MM-DD")` |
  | 剩余一路到底 | `ds_replay(resume_run_id, to_end=true)` |
- **方向落点**：`induction_notes` 成为**下一周期**因子退役评估的 `user_notes`（复用既有通道）。
- **rewind**：`rewind_to=D` 恢复到"D 当天开始"的线上状态（用 `<D-1>__post-day` 当日终态快照，首日回起点），并截断 D 及其后的轨迹/检查点；纯 rewind（未同时给方向/to_end）只回退并把控制权交回用户。
- 暂停期间**不还原**线上状态（供续跑）；跑到 `end` 或 `to_end` 才终态检查点 + 报告 + 可选 `restore_after` 还原。

### 5.2 代码改动
- `reflect.js`：新增 `streamText(ctx, prompt, {provider,model,maxTokens,temperature})`——旁路 LLM 自由文本（不强制 JSON），用于方向建议。
- `replay.js`：把 `runReplay` 重构为**可分段/可续跑会话**：
  - `dayListOf(start,end)`；session 持久化 `sessionPath/loadSession/saveSession`（parent/signal/onProgress 不落盘）；
  - `runReplayDay(...)`：抽出单日全管线（2.1 数据 → 2.2 分析 → pre-settle → 2.3 结算 → pre-factor → 2.4 因子流(反思/A 非alpha/B alpha barrier) → 2.5 周期退役），末尾新增 `<day>__post-day` 当日终态快照，返回 `{reviewDone}`；
  - `replaySegment`：从 `s.next_idx` 逐日跑，interactive 在周期边界（做了退役且非最后一天）暂停；
  - `buildDirectionSuggestion`：启发式（每狗退役/休眠/低信息 + 周期 PnL 趋势 → 保留/收紧/观察建议）+ 可选 LLM 润色（失败回退启发式）；
  - `pauseReplay` / `rewindSession` / `finalizeReplay` / `resumeReplay`；
  - `runReplay`：`opts.resume_run_id` 走 `resumeReplay`；否则全新回放（快照起点 → reset → prepareRange → matches 快照 → 建 session → segment → pause/finalize）；异常兜底还原起点。
  - **auto 模式行为不变**。
- `tools/headless.js` `ds_replay`：新增参数 `mode/interactive/resume_run_id/induction_notes/rewind_to/to_end`；`start/end` 改为非必填（续跑忽略）；续跑分支只透传续跑参数。
- `docs/replay_mode.md`：补「运行方式：一路到底 / 半交互续跑」章节 + `__post-day` 检查点说明。

### 5.3 关键落盘产物
- `<cacheDir>/replays/<run_id>/session.json`：会话状态（config + 进度 `next_idx` + 累积 trajectory/reviewLog/checkpointLog/log + `status` + `pending_direction`）。
- `checkpoints/<day>__pre-settle | __pre-factor | __post-day`、`<end>__post-factor`；`snapshot/`（起点）；`report.json` / `report.md` / `replay.log.json`。
