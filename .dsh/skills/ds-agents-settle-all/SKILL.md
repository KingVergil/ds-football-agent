# 全部结算（结算流）

对 7 只单关狗（不含串关2狗）并行结算。串关2狗归 Python 侧，跳过。

## 唯一步骤（一次工具调用，禁止逃逸）

**直接调 `ds_settle_all(day=<足球日>, parallel=7)` 一次**，它就是结算流的全部：
工具内部会先做数据准备（刷新比分缓存）再并行结算 7 只狗，每狗进度写入任务状态，无任何 LLM 介入。

⚠️ 硬性约束（防逃逸，这是之前步骤过多的根因）：
- **禁止**用 bash / glob / find / 读文件去探查日期、缓存、订单、比分——日期由你直接推断
  （"0816" → `2026-08-16`；12:00 前的"昨天"同理），并把推断结果作为 `day` 传给工具。
- **禁止**在调用前后手动检查 matches 文件、roles 文件或 storage——工具返回里已有结论。
- 工具返回后直接汇报：每狗 结算数 / 未结算数 / PnL、`missing_scores`（如有）、`warnings`（如有）。
  若 `settled=0` 且有 `missing_scores`，把 missing 列表原样给用户即可，**不要自己翻文件排查**。
- 反思 / 因子归纳 / 因子退役 不属于结算流，本次不要调用。

## 说明

- 结算 + 反思 + 因子归纳/退役的完整日流程见回放模式（`ds_replay`）；独立因子操作走 `ds_factor_flow`。
- 若某狗 `unsettled=0`（无待结算单），结算流直接跳过，进度照常推进。
